## Compute

Grounding DINO is the bottleneck. DINO embedding is cheap. On a Jetson Orin NX, the original model runs at about 1.1 frames per second. Grounding DINO 1.5 Edge reaches 10.7 frames per second. A memory aid that samples one frame every few seconds needs only about 1 frame per second.

| Component | Options | Notes |
|-----------|---------|-------|
| Detector | Grounding DINO Tiny (Swin-T) or Base. Base has about 0.2 billion parameters. | Open weights. Supported by Hugging Face Transformers. |
| Detector, faster | Grounding DINO 1.5 Edge | Check if weights are available for on-device use. |
| Detector, strongest | Grounding DINO 1.5 Pro | Server side. Same check. |
| Embedder, small | DINOv3 ViT-S/16 (21 M) | Phone or hub friendly. |
| Embedder, default | DINOv3 ViT-B/16 (86 M) or DINOv2 ViT-B/14 | Good balance. |
| Embedder, accurate | DINOv3 ViT-L/16 (300 M) or DINOv2 ViT-L/14 | Server. |
| Verifier (optional) | SuperPoint with LightGlue. A small vision-language model. | Runs on borderline sightings only. |

The code uses Grounding DINO Tiny and DINOv2-small. The vector size is 384.

## Deployment options

- **Home hub** (Jetson-class or a mini PC). It runs a small detector and a small embedder. The archive and tables are local. Frames never leave the home.
- **Phone and server.** The phone captures and filters frames. A server runs the larger models. This is the simplest to build. Images leave the home, so consent and retention rules matter more.
- **Batching.** Process frames in small batches every minute. The last-seen record is still only minutes old.

## Evaluation

Measure the detector and the identity step separately. They fail for different reasons.

| Metric | Measures | Target |
|--------|----------|--------|
| Detector recall for each object | The detector finds the object when it is visible. | Very high |
| Identity precision | Accepted sightings that are the owner's item. | Highest priority |
| Look-alike rejection rate | Registered negatives that the system refuses. | Report separately |
| Last-seen accuracy | The answer matches the true last sighting within a time tolerance. | The main number |
| "Not seen" rate | Questions with no record. | Watch for strict thresholds |
| Latency for each frame | Ingestion time on the target hardware. | Below the sampling interval |

Ablations:

- DINOv2 against DINOv3, base against large.
- Box pooling against SAM-mask pooling against crop embedding.
- Category-only prompt against category plus synonyms against a generic "object" prompt.
- With and without the look-alike margin. With and without verification.
- Number of enrollment views (1, 3, 5, 10).

## Risks and mitigations

| Risk | Effect | Mitigation |
|------|--------|------------|
| A near-identical look-alike | Wrong last-seen answer | Register it as a negative. Require a margin. Check marks with a vision-language model. Hedge the answer if the margin is small. |
| The category word describes the object badly | The detector never proposes it | Add synonyms. Run a generic pass now and then. Consider SAM automatic masks as a second source. |
| A small or hidden object | Weak embedding, missed match | Embed a crop. Raise the input size. Add views from confirmed sightings. |
| The patient carries the object | "Last seen" points to a place that is no longer correct | Flag hand overlap. Answer, "You were holding it at ...". |
| The object changes (lid off, phone case on) | The match drops below the threshold | Register each state as a view. |
| A model update changes the scores | Silent loss of accuracy | Freeze model versions. Calibrate on the pilot set before release. |
| Privacy of images from the home | Loss of trust, consent problems | Process on a home hub. Keep crops, not frames. Use recording-free zones. |
