The `db` component stores image metadata in SQLite (with the `peewee` ORM). It stores the region vectors in a FAISS index. `Region.id` is the vector id. The component keeps the tables and the index in step.

## Rules

- The component does not control the application flow. `backend` does.
- Each helper does one storage job.
- `backend` uses `db/api.py` only. It does not open the SQLite file or the FAISS file.
- The component does not read or write image files, and it does not make embeddings.

## Files

| File | Purpose |
|------|---------|
| `schema.py` | The `Image` and `Region` tables. |
| `api.py` | Config loader, `init_db`, query helpers, vector helpers, start-up recovery. |
| `vector_index.py` | The FAISS index. It has no database code. |
| `errors.py` | Error classes. |
| `config.toml` | Paths and vector settings. |

## Configuration

All paths are relative to the `db/` folder. Absolute paths and paths that leave the folder are not allowed.

```toml
[paths]
sqlite = "data/saarthi.db"
faiss_index = "data/regions.faiss"

[vectors]
dimension = 384
checkpoint_every = 200
```

The index is saved after `checkpoint_every` added or removed vectors. It is also saved when the application stops. A crash can lose at most that number of vectors. The start-up recovery repairs the loss.

## Usage

```python
from db.api import init_db, startup_recovery, checkpoint_vectors

database, config = init_db()
report = startup_recovery()
# ... run the application ...
checkpoint_vectors()  # When the application stops
```

`init_db` opens the database and the index, and creates missing tables. You can call it more than one time.

## Query helpers

| Helper | Task |
|--------|------|
| `add_image` | Insert an image with the status `pending`. |
| `find_image_by_sha256` | Find an image with the same hash (exact duplicate). |
| `list_recent_phashes` | List perceptual hashes of `done` images, newest first. |
| `get_image` | Read one image. |
| `claim_next_pending` | Set the oldest `pending` image to `processing`. |
| `set_image_analysis` | Save `phash` and `blur_score` of a `processing` image. |
| `add_regions` | Insert the regions of a `processing` image. |
| `get_regions` | Read the regions of an image. |
| `mark_image_done` | Set a `processing` image to `done`. |
| `mark_image_rejected` | Set a `processing` image to `rejected`, with a reason. |
| `mark_image_failed` | Set a `processing` image to `failed`, with an error text. |
| `list_images_older_than` | List finished images captured before a time (retention). |
| `delete_images` | Delete images, regions, and vectors. Return the file paths for `storage`. |
| `list_image_paths` | List the file path of every image. |

## Vector helpers

| Helper | Task |
|--------|------|
| `store_region_vectors` | Add vectors to the index and mark the regions as embedded. It does both or none. |
| `remove_region_vectors` | Remove vectors from the index and clear the marks. |
| `checkpoint_vectors` | Write the index to disk now. |
| `vector_count` | The number of vectors in the index. |
| `list_vector_ids` | The region ids that have a vector. |

`store_region_vectors` needs a `float32` array. It needs one row of unit length for each region id.

## Start-up recovery

Call `startup_recovery()` one time after `init_db()` and before the workers start. It repairs the tables and the index after a stop. It returns a `StartupReport`. The backend writes the report to the log.

**Rule:** every region of a `done` image must have a vector. If a region has no vector, the recovery sets its image back to `pending`.

## Errors

| Error | Meaning |
|-------|---------|
| `ConfigError` | `config.toml` is missing or not correct. |
| `DbError` | Base class. Also used for other database errors. |
| `DuplicateImageError` | `file_path` or `sha256` is already in the database. |
| `InvalidStateError` | The image does not exist or has the wrong status. |
| `InvalidRecordError` | The database refuses a value. |
| `VectorIndexError` | The index refuses the call. For example, an id is already in the index. |
